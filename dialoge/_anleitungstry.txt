#  alle Dateien und sagt dir mit Zeilennummer, was nicht stimmt.
# ===========================================================================

#    nichts_offen    es gibt keine offenen Auftraege

#    abend           18 bis 22 Uhr
#    nacht           nach 22 Uhr

#    wochenende      Samstag und Sonntag
#
#  PLATZHALTER (in geschweiften Klammern)
#    {anrede}       Dave, bei Verzug foermlicher
#    {name}         Dave
#    {offen}        Anzahl offener Auftraege
#    {ueberfaellig} Anzahl ueberfaelliger Auftraege

#    {datum}        heutiges Datum
#    {zeit}         aktuelle Uhrzeit
#    {schiff}       USCSS DISCOVERY

#  Lange Texte darfst du umbrechen: eine eingerueckte Folgezeile
#  haengt automatisch an der vorigen.

# ===========================================================================
#  ZWEITE ART VON DATEI: GESPRAECHSPARTNER
# ---------------------------------------------------------------------------
#  Hat eine Datei die Zeile  PARTNER: <name>  , dann ist sie kein Dialog,
#  sondern legt fest, wie jemand auf eine Ansprache antwortet.
#
#  Beispiel (siehe partner_ripley.txt):
#
#      PARTNER: ripley
#      KUERZEL: r
#
#      HALLO: Morgen. Fangen wir an.
#      HALLO: Hey. Alles unter Kontrolle hier?
#      REPORT: {offen_text}, davon {ueberfaellig} ueberfaellig.
#      BYE: Bis morgen. Mach nicht zu lange.
#      SONST: Keine Ahnung. Frag MU/TH/UR, der weiss sowas.
#
#  Angesprochen wird mit @ und dem Kuerzel:   @r hallo
#
#  PARTNER kann sein: muthur, wy, dave, ripley, ash, newt
#  KUERZEL ist frei waehlbar, ueblich der erste Buchstabe.
#
#  THEMEN (jedes beliebig oft, es wird zufaellig gewaehlt):
#    HALLO    hallo, hi, hey, moin, servus, guten tag, na
#    DANKE    danke, merci, thx, vielen dank
#    REPORT   report, bericht, meldung, lage, lagebericht
#    STATUS   status, wie gehts, alles klar, wie laeuft
#    WER      wer, wer bist du, identifikation, ausweis
#    SORRY    sorry, entschuldigung, tut mir leid, verzeihung
#    BYE      bye, tschuess, ciao, bis spaeter, feierabend, gute nacht
#    SONST    Antwort, wenn das Thema nicht erkannt wurde
#
#  Zusaetzliche Platzhalter mit richtiger Mehrzahl:
#    {offen_text}         '1 offener Posten' oder '3 offene Posten'
#    {ueberfaellig_text}  dasselbe fuer Ueberfaellige
#    {erledigt_text}      '1 Vorgang' oder '4 Vorgaenge'
# ===========================================================================

# ===========================================================================
#  DRITTE ART: GESCHICHTE
# ---------------------------------------------------------------------------
#  Hat eine Datei die Zeile  AN: <partner>  und STICHWORT, dann gehoert sie
#  zur Geschichte. Sie wird nicht zufaellig gesendet, sondern erscheint,
#  wenn du den Partner darauf ansprichst:
#
#      AN: ripley
#      STICHWORT: reaktor, antrieb, maschinenraum
#
#  Aufruf dann:   @r reaktor
#
#  MERKER halten fest, was passiert ist. ZAEHLER messen Verhaeltnisse.
#
#      SETZE: ripley_unterwegs          Merker setzen
#      SETZE_JA: kuehlleitung_gemeldet  nur bei der Antwort ja
#      SETZE_NEIN: tuer_blieb_zu        nur bei nein
#      LOESCHE: ripley_unterwegs        Merker wieder entfernen
#      ZAEHLE: vertrauen_ripley +1      Zaehler aendern (auch -1)
#      ZAEHLE_NEIN: ash_zufrieden -1
#
#  SPAETER schickt jemanden los, der sich dann von allein zurueckmeldet:
#
#      SPAETER_JA: reaktor_02 nach 4    taucht in 4 Eingaben auf
#
#  BEDINGUNG kann jetzt auch auf Merker und Zaehler pruefen. Mehrere
#  BEDINGUNG-Zeilen muessen alle zutreffen:
#
#      BEDINGUNG: merker reaktor_geprueft
#      BEDINGUNG: nicht merker ripley_unterwegs
#      BEDINGUNG: zaehler vertrauen_ripley >= 2
#
#  'story' zeigt alle Merker, Verhaeltnisse und laufenden Auftraege.
#  Alles liegt in daten/story.json.
#
#  Die Dateien reaktor_01, reaktor_02 und ash_fragt_nach sind eine kleine
#  Beispielgeschichte. Sprich Ripley mit  @r reaktor  an.
# ===========================================================================

# ===========================================================================
#  NOTIZDATEIEN
# ---------------------------------------------------------------------------
#  Faengt ein Dateiname mit einem Unterstrich an, ist die Datei eine Notiz:
#
#      _anleitung.txt    diese Datei
#      _ideen.txt        deine Ideensammlung
#      _entwurf.txt      eine halbfertige Szene
#
#  Notizen werden gelesen, aber nie verwendet: sie tauchen nicht als
#  Durchsage auf, antworten auf kein Stichwort und werden nicht auf Fehler
#  geprueft. Du kannst darin schreiben, was du willst. 'dialog' listet sie
#  als 'Notiz' mit auf, damit du weisst, dass sie da sind.
#
#  Eine halbfertige Szene legst du also still, indem du die Datei von
#  'reaktor_03.txt' in '_reaktor_03.txt' umbenennst.
# ===========================================================================
